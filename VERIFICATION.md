## Исторические проверки первой версии с конусом (Three.js r160)

Проверки разработки выполнены локально. Ниже также описана проверка статической сборки перед публикацией отдельного репозитория `NQUAREx/DinoPlat3d`.

- `npm run build`: TypeScript и production-сборка Vite прошли. JavaScript ~469 КБ, ~120 КБ gzip; CSS ~5.2 КБ. Единственная runtime-зависимость — Three.js.
- `npm test`: 8 тестов прошли. Проверены четыре полосы, реальная позиция при перестроении, пересечение препятствия между шагами, прыжки на начальной и максимальной скорости, пауза / сброс, запас времени маршрута, независимость симуляции от частоты кадров.
- Генерация: 100 начальных значений × 300 секунд на максимальной скорости, с задержкой реакции 300 мс, без прыжков. Все забеги проходимы; буферы не заменяются и остаются фиксированного размера.
- `npm run test:browser`: production preview + headless Chromium, desktop 1440×900, mobile 390×844 с touch и DPR 3, landscape 844×390. Пройдены клавиши, касания половин экрана, вертикальный и горизонтальный свайпы, столкновение, Game Over, рестарт, рекорд после перезагрузки, пауза, resize, WebGL 1, запрет localStorage и потеря / восстановление WebGL-контекста. Необработанных JS-ошибок нет.
- При проверке обнаружено подавление совместимого `click` сразу после свайпа. Исправлено: touch-кнопки обрабатывают `pointerup`, повторный click отсекается. Финальная последовательность свайп → пауза → поворот → продолжение прошла.
- GPU-счётчики: 6 draw calls, 2 геометрии, 0 текстур. В одном измеренном кадре — 696 треугольников. Количество треугольников меняется с количеством видимых кубов.
- После 100 перезапусков: JS heap после принудительного GC 3 985 987 → 4 030 551 байт (+44 564 байта); число геометрий и текстур не изменилось. Это ограниченная проверка стабильности, а не доказательство отсутствия любых утечек.
- Во время 12-секундного рендеринга с автоматической подачей команд движения: 702 кадра за 12 004 мс; средний интервал 17.10 мс, p95 16.8 мс. Буфер 1200×750. Это результат headless Chromium в облачном окружении с разрешённым SwiftShader, не характеристика физических мобильных устройств.

Физические старые телефоны, Safari и Firefox не тестировались. Для вывода о производительности на конкретном устройстве нужен отдельный длительный прогон. Повторяемые тесты находятся в `tests/`, свежие отчёт и скриншоты создаются в `test-results/`.
