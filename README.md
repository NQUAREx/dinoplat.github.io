# DinoPlat3d

Светлый детский пиксельный раннер на TypeScript и Three.js **0.186.1**. Пять полос, белый низкополигональный динозавр, белые кубы и песчаная дорожка. Мятный фон, зелёные пиксельные кнопки и локальный шрифт с кириллицей. Этот репозиторий независим от действующей игры в `NQUAREx/dinoplat.github.io`.

**Играть:** https://nquarex.github.io/DinoPlat3d/ (после успешной публикации Pages).

## Нужен ли сервер

**Игровой сервер / backend не нужен.** Вся логика выполняется в браузере, рекорд хранится локально через localStorage. Игра не делает API-запросов, не использует WebSocket, базу данных или серверную авторизацию. Для игры достаточно статического HTTPS-хостинга GitHub Pages.

Node.js и Vite используются только для разработки и получения сборки. GitHub Actions выполняет `npm ci`, тесты и `npm run build`, после чего публикует файлы `dist/index.html` и `dist/assets/*`. При открытии игры Node.js и Vite не запускаются. Исходники TypeScript непосредственно в Pages публиковать не следует: браузеру нужна готовая сборка.

## Как включить GitHub Pages вручную

1. Открыть https://github.com/NQUAREx/DinoPlat3d/settings/pages под владельцем репозитория.
2. В разделе **Build and deployment** выбрать **Source → GitHub Actions**. Если выбора нет, проверить права администратора и доступность Pages для репозитория.
3. Открыть **Actions → Build and deploy static game**: https://github.com/NQUAREx/DinoPlat3d/actions/workflows/pages.yml.
4. Нажать **Run workflow**, выбрать ветку `main` и подтвердить запуск. Если первый запуск упал до включения Pages, можно нажать **Re-run all jobs**.
5. Дождаться зелёных заданий `build` и `deploy`. После публикации открыть https://nquarex.github.io/DinoPlat3d/. На странице **Settings → Pages** также появится ссылка **Visit site**.

Дальнейшие push в `main` автоматически обновляют игру. Workflow расположен в `.github/workflows/pages.yml`, публикует только статическую сборку `dist/` и не затрагивает другие репозитории. Для Source **GitHub Actions** не нужно выбирать папку `/docs` или создавать ветку `gh-pages`.

Если workflow отключён, сначала разрешить его в **Actions**. Если шаг публикации требует подтверждения окружения `github-pages`, подтвердить его на странице запуска. При ошибке Pages после изменения настроек повторить запуск workflow.

## Запуск

Для разработки: Node.js 22+ и npm.

```sh
npm ci
npm run dev
```

Открыть адрес Vite в браузере. Телефон в той же сети может открыть показанный Vite сетевой адрес.

```sh
npm run build
npm run preview
```

Содержимое `dist/` — обычный статический сайт, без серверной игровой логики и внешних CDN. Его можно разместить на GitHub Pages или любом HTTP-хостинге, в том числе в подкаталоге. Относительная база настроена в Vite. Исходный `index.html` работает через Vite; для обычного статического сервера нужен именно `dist/`. Запуск через `file://` не поддерживается браузерными ES-модулями.

Для GitHub Pages добавлен `.github/workflows/pages.yml`: после включения Pages он собирает и публикует `dist/` при push в `main`. `base: './'` в Vite обеспечивает относительные пути к ресурсам, включая размещение по адресу `/DinoPlat3d/`.

## Управление

- Телефон: короткое касание левой / правой половины экрана меняет полосу; свайп вверх — прыжок. Горизонтальные свайпы также поддерживаются. Один жест совершает одно действие.
- Клавиатура: ← / → или A / D — полосы; ↑, W или пробел — прыжок; Esc / P — пауза; Enter — старт / продолжение.
- Кнопка паузы доступна и на телефоне. При уходе со вкладки игра останавливается и ждёт явного продолжения.
- После столкновения доступны дистанция, локальный рекорд и новый забег. Отказ в доступе к localStorage не мешает играть.

Игра имеет только **вертикальную компоновку**. На ПК вертикальное игровое поле расположено по центру окна; на телефоне при повороте в горизонтальное положение показывается просьба повернуть устройство, а симуляция и RAF останавливаются. После возвращения в вертикальное положение нужно нажать «Продолжить». Альбомной камеры и отдельной горизонтальной компоновки нет. Все меню, кнопки, HUD и подсказки центрированы относительно игрового поля.

Основные правила стиля, архитектуры, производительности и публикации закреплены в [AGENTS.md](AGENTS.md). Источники и лицензии шрифта / песка — в [ASSETS.md](ASSETS.md).

## Устройство

`src/simulation.ts` содержит только правила и числовое состояние: генератор, движение, прыжок, коллизии. Не зависит от DOM или Three.js.

`src/view.ts` владеет сценой и GPU-ресурсами. `src/dinosaur.ts` однократно загружает GLB через GLTFLoader, запекает преобразования в геометрию и освобождает временные ресурсы. На старте есть состояние загрузки и повторная попытка при ошибке. Положение динозавра берётся из `Simulation.x/y`, коллайдер отделён от геометрии. Лёгкое покачивание при беге не требует скелета или обновления вершин. Текстур и внешних декодеров нет.

`src/input.ts` распознаёт клавиши, касания и свайпы. `src/main.ts` связывает компоненты, ведёт RAF, состояния экрана, рекорд и жизненный цикл.

`LANES = 5`, стартовая полоса — центральная (индекс 2, X=0). Положение полос, ширина дороги 10.5 м, четыре разделителя и пул до 48 кубов выведены из общих констант. Камера повёрнута дополнительно на 10° сверху вокруг прежней точки наблюдения; все пять полос помещаются в кадре на уровне персонажа.

## Почему маршрут проходим

В каждом ряду есть гарантированная свободная полоса. Она меняется не более чем на одну полосу относительно предыдущего ряда. Остальные четыре полосы заполняются случайно; полностью пустых или полностью перекрытых рядов нет. Это гарантия существования маршрута, а не защита от неправильного выбора игрока.

Между рядами 18 м, максимальная скорость 24 м/с. После учёта длины зоны столкновения остаётся `(18 − 2 × (0.6 + 0.27)) / 24 = 0.6775` секунды для перехода. Смена полосы занимает `2.1 / 13 ≈ 0.162` секунды. Даже с реакцией 300 мс есть запас. Первый ряд начинается через 42 м. Прыжок не требуется для доказанного пути, но позволяет перепрыгивать кубы.

Коллизии проверяются по реальному положению, а не целевой полосе: swept AABB по горизонтальным осям с проверкой высоты ног. Это намеренно простой, слегка прощающий коллайдер тела динозавра; декоративный хвост не создаёт отдельной зоны столкновения. Ступни модели находятся на высоте ноль, ширина до поворота меньше диаметра коллайдера 0.54 м. Шаг симуляции 1/120 с, отрисовка через RAF. При длительном зависании включается пауза; на обычных 15/30/60/120 Гц правила одинаковы.

## Ограничение нагрузки

- Пул из 12 рядов: постоянные typed arrays, координаты постоянно возвращаются в локальный диапазон, накопления объектов и мировой координаты нет.
- До 48 кубов в одном InstancedMesh; невидимые дальние ряды не загружаются в draw count. Геометрии куба и динозавра создаются один раз и переиспользуются после перезапусков.
- Шесть вызовов отрисовки в обычной сцене, два объекта геометрии, **одна текстура** песка 256×256 (~12 КБ WebP) с mipmaps. У динозавра 288 треугольников, один меш, один материал и vertex colours для глаз; сам персонаж без текстур. GLB ~27 КБ. Шрифт Press Start 2P ~30 КБ WOFF2 загружается локально. Без теней, постобработки, звука и CDN.
- Ограничение DPR до 1.25 и буфера до 900 000 пикселей. При медленных кадрах масштаб постепенно падает до 0.5; обратное повышение имеет задержку, чтобы избежать постоянных переключений.
- В меню, паузе и Game Over непрерывный RAF выключен. Все обработчики и GPU-ресурсы освобождаются при уничтожении приложения / HMR.
- Three.js 0.186.1 требует **WebGL 2**, ES2018 и Pointer Events. Поддержка WebGL 1 была удалена из Three.js начиная с r163: обновление с r160 сознательно меняет нижнюю границу совместимости. При отсутствии WebGL 2 показывается понятное сообщение. Конкретный FPS на старых устройствах не обещается.

## Динозавр и Blender Python

Модель создана с нуля скриптом через встроенный Python Blender **4.3.2**. Установка `bpy` из pip для игры не нужна. Blender требуется только для редактирования или повторного экспорта модели; GitHub Actions и браузер используют уже готовый GLB.

- `art/dinosaur.blend` — редактируемая исходная модель.
- `tools/create_dinosaur.py` — воспроизводимый генератор: тело, голова, хвост, лапы и глаза объединены в один меш.
- `src/assets/dinosaur.glb` — самостоятельный glTF 2.0 с геометрией, нормалями и цветами вершин. Без UV, текстур, скелета и анимационных клипов.

```sh
npm run model:build
# или blender --background --factory-startup --python tools/create_dinosaur.py
```

Ось взгляда в игре — −Z, вверх — +Y, начало координат находится на уровне ступней. После изменения модели запустить `npm test` и `npm run build`. Ни `.blend`, ни Blender не передаются игроку; Vite публикует только GLB в `dist/assets/`.

Для этой работы установлены в окружение и использованы навыки [threejs-geometry](https://github.com/CloudAI-X/threejs-skills/blob/b1c623076c661fc9b03dac19292e825a5d106823/skills/threejs-geometry/SKILL.md) и [threejs-loaders](https://github.com/CloudAI-X/threejs-skills/blob/b1c623076c661fc9b03dac19292e825a5d106823/skills/threejs-loaders/SKILL.md). Они помогли сохранить один draw call для персонажа, загрузить GLB один раз и освобождать временные геометрии и материалы. Это инструкции для разработки, не runtime-зависимости игры. Источник — `CloudAI-X/threejs-skills`, commit `b1c623076c661fc9b03dac19292e825a5d106823`; локальная установка: `/home/agent/.agents/skills/threejs-geometry` и `/home/agent/.agents/skills/threejs-loaders`.

## Проверка

```sh
npm test
npm run build
npx playwright install chromium  # если системного Chromium нет
npm run test:browser
```

Браузерный тест сам поднимает production preview на 4174. Можно задать `CHROMIUM_PATH`. Проверяет пять полос, запас пула, угол камеры +10°, видимость крайних полос, центрирование меню, загрузку пиксельного шрифта, песка и динозавра; клавиатуру и touch, прыжок, столкновение, перезапуск, рекорд и паузу. Проверяет экран поворота и остановку симуляции при горизонтальном положении, обязательное ручное продолжение, меню на 320×568, WebGL 2, запрет localStorage, ошибки загрузки GLB / песка и восстановление графического контекста. После 100 перезапусков сравнивает число геометрий / текстур и heap после GC. Отчёт и скриншоты — в игнорируемом `test-results/`. Отдельный тест GLB проверяет компактность и отсутствие текстур именно у персонажа.

Тест симуляции проходит 100 начальных значений по пять минут на максимальной скорости, следуя безопасному пути с задержкой реакции 300 мс. Это ускоренная симуляция, не 500 минут рендеринга на реальном телефоне. Короткий headless-прогон и стабильные счётчики не доказывают отсутствие любых утечек; длительные замеры на физических слабых устройствах ещё нужны.

`?debug` явно включает `window.__runner` для проверки состояния и `stats()` (draw calls, треугольники, GPU-ресурсы, разрешение). Без параметра диагностический доступ отсутствует.

## Исходная игра: наблюдения

Запущена в Chromium в мобильном размере 390×844. По обычному URL загрузка темы ломалась (`resources/themes/false/...`, ошибки `drawImage`). С `?t=dinosaur` видны песчаный фон, динозавр снизу, кактусы, монеты, три сердца и пять полос. Проверены старт, перемещение касанием и пауза.

Оценка исходной реализации: 5/10 как любительского прототипа. Плюсы — работающий цикл, темы, бонусы, повторное использование рядов. Недостатки — монолитный класс, расширение Array.prototype, коллизии по целевой полосе вместо отображаемой позиции, ускорение на кадр вместо времени, таймеры с состоянием между забегами, отсутствие клавиатуры и обработки resize. Это оценка просмотренного кода и короткой игровой сессии, не полный аудит.
