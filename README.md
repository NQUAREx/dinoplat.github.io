# DinoPlat3d

Бесконечный браузерный раннер, написанный заново на TypeScript и Three.js. Четыре полосы, белый конус, белые кубы. Ассеты и игровая реализация прежней 2D-версии не используются. Этот репозиторий независим от действующей игры в `NQUAREx/dinoplat.github.io`.

**Играть:** https://nquarex.github.io/DinoPlat3d/ (после успешной публикации Pages).

## Нужен ли сервер

**Игровой сервер / backend не нужен.** Вся логика выполняется в браузере, рекорд хранится локально через localStorage. Игра не делает API-запросов, не использует WebSocket, базу данных или серверную авторизацию. Для игры достаточно статического HTTPS-хостинга GitHub Pages.

Node.js и Vite используются только для разработки и получения сборки. GitHub Actions выполняет `npm ci`, тесты и `npm run build`, после чего публикует файлы `dist/index.html` и `dist/assets/*`. При открытии игры Node.js и Vite не запускаются. Исходники TypeScript непосредственно в Pages публиковать не следует: браузеру нужна готовая сборка.

## Как включить GitHub Pages вручную

1. Открыть https://github.com/NQUAREx/DinoPlat3d/settings/pages под владельцем репозитория.
2. В разделе **Build and deployment** выбрать **Source → GitHub Actions**. Если выбора нет, проверить права администратора и доступность Pages для репозитория.
3. Открыть **Actions → Build and deploy static game**: https://github.com/NQUAREx/DinoPlat3d/actions/workflows/pages.yml.
4. Нажать **Run workflow**, выбрать ветку `main` и подтвердить запуск. Если первый запуск упал до включения Pages, можно нажать **Re-run all jobs**.
5. Дождаться зелёных заданий `build` и `deploy`. После публикации открыть https://nquarex.github.io/DinoPlat3d/. На странице **Settings → Pages** также появится ссылка **Visit site**.

Дальнейшие push в `main` автоматически обновляют игру. Workflow расположен в `.github/workflows/pages.yml`, публикует только статическую сборку `dist/` и не затрагивает другие репозитории. Для Source **GitHub Actions** не нужно выбирать папку `/docs` или создавать ветку `gh-pages`.

Если workflow отключён, сначала разрешить его в **Actions**. Если шаг публикации требует подтверждения окружения `github-pages`, подтвердить его на странице запуска. При ошибке Pages после изменения настроек повторить запуск workflow.

## Запуск

Для разработки: Node.js 22+ и npm.

```sh
npm ci
npm run dev
```

Открыть адрес Vite в браузере. Телефон в той же сети может открыть показанный Vite сетевой адрес.

```sh
npm run build
npm run preview
```

Содержимое `dist/` — обычный статический сайт, без серверной игровой логики и внешних CDN. Его можно разместить на GitHub Pages или любом HTTP-хостинге, в том числе в подкаталоге. Относительная база настроена в Vite. Исходный `index.html` работает через Vite; для обычного статического сервера нужен именно `dist/`. Запуск через `file://` не поддерживается браузерными ES-модулями.

Для GitHub Pages добавлен `.github/workflows/pages.yml`: после включения Pages он собирает и публикует `dist/` при push в `main`. `base: './'` в Vite обеспечивает относительные пути к ресурсам, включая размещение по адресу `/DinoPlat3d/`.

## Управление

- Телефон: короткое касание левой / правой половины экрана меняет полосу; свайп вверх — прыжок. Горизонтальные свайпы также поддерживаются. Один жест совершает одно действие.
- Клавиатура: ← / → или A / D — полосы; ↑, W или пробел — прыжок; Esc / P — пауза; Enter — старт / продолжение.
- Кнопка паузы доступна и на телефоне. При уходе со вкладки игра останавливается и ждёт явного продолжения.
- После столкновения доступны дистанция, локальный рекорд и новый забег. Отказ в доступе к localStorage не мешает играть.

## Устройство

`src/simulation.ts` содержит только правила и числовое состояние: генератор, движение, прыжок, коллизии. Не зависит от DOM или Three.js.

`src/view.ts` владеет сценой и GPU-ресурсами. Для добавления 3D-модели достаточно заменить представление игрока здесь; положение берётся из `Simulation.x/y`. Игровой коллайдер намеренно отделён от геометрии. Если размер модели отличается, параметры коллайдера следует согласовать отдельно.

`src/input.ts` распознаёт клавиши, касания и свайпы. `src/main.ts` связывает компоненты, ведёт RAF, состояния экрана, рекорд и жизненный цикл.

## Почему маршрут проходим

В каждом ряду есть гарантированная свободная полоса. Она меняется не более чем на одну полосу относительно предыдущего ряда. Остальные три полосы заполняются случайно; полностью пустых или полностью перекрытых рядов нет. Это гарантия существования маршрута, а не защита от неправильного выбора игрока.

Между рядами 18 м, максимальная скорость 24 м/с. После учёта длины зоны столкновения остаётся `(18 − 2 × (0.6 + 0.27)) / 24 = 0.6775` секунды для перехода. Смена полосы занимает `2.1 / 13 ≈ 0.162` секунды. Даже с реакцией 300 мс есть запас. Первый ряд начинается через 42 м. Прыжок не требуется для доказанного пути, но позволяет перепрыгивать кубы.

Коллизии проверяются по реальному положению, а не целевой полосе: swept AABB по горизонтальным осям с проверкой высоты ног. Это намеренно простой, слегка прощающий коллайдер конуса. Шаг симуляции 1/120 с, отрисовка через RAF. При длительном зависании включается пауза; на обычных 15/30/60/120 Гц правила одинаковы.

## Ограничение нагрузки

- Пул из 12 рядов: постоянные typed arrays, координаты постоянно возвращаются в локальный диапазон, накопления объектов и мировой координаты нет.
- До 36 кубов в одном InstancedMesh; невидимые дальние ряды не загружаются в draw count. Геометрии куба и конуса создаются один раз.
- Шесть вызовов отрисовки в обычной сцене, два объекта геометрии, ноль текстур. Без теней, постобработки, загрузки моделей, звука и внешних шрифтов.
- Ограничение DPR до 1.25 и буфера до 900 000 пикселей. При медленных кадрах масштаб постепенно падает до 0.5; обратное повышение имеет задержку, чтобы избежать постоянных переключений.
- В меню, паузе и Game Over непрерывный RAF выключен. Все обработчики и GPU-ресурсы освобождаются при уничтожении приложения / HMR.
- Three.js r160 выбрана ради WebGL 1, который удалён в новых версиях. Нужен WebGL 1 с ANGLE_instanced_arrays или WebGL 2, а также поддержка ES2018 и Pointer Events. Совместимость с любым старым браузером или заданный FPS на любом телефоне не обещаются.

## Проверка

```sh
npm test
npm run build
npx playwright install chromium  # если системного Chromium нет
npm run test:browser
```

Браузерный тест сам поднимает production preview на 4174. Можно задать `CHROMIUM_PATH`. Он проверяет клавиатуру, настоящие touch-события через Chromium, прыжок, столкновение, перезапуск, рекорд, паузу, смену ориентации, WebGL 1, запрет localStorage и восстановление GPU-контекста. После 100 перезапусков сравнивает число GPU-ресурсов и JS heap после принудительной сборки мусора. Скриншоты и измерения пишет в игнорируемый `test-results/`.

Тест симуляции проходит 100 начальных значений по пять минут на максимальной скорости, следуя безопасному пути с задержкой реакции 300 мс. Это ускоренная симуляция, не 500 минут рендеринга на реальном телефоне. Короткий headless-прогон и стабильные счётчики не доказывают отсутствие любых утечек; длительные замеры на физических слабых устройствах ещё нужны.

`?debug` явно включает `window.__runner` для проверки состояния и `stats()` (draw calls, треугольники, GPU-ресурсы, разрешение). Без параметра диагностический доступ отсутствует.

## Исходная игра: наблюдения

Запущена в Chromium в мобильном размере 390×844. По обычному URL загрузка темы ломалась (`resources/themes/false/...`, ошибки `drawImage`). С `?t=dinosaur` видны песчаный фон, динозавр снизу, кактусы, монеты, три сердца и пять полос. Проверены старт, перемещение касанием и пауза.

Оценка исходной реализации: 5/10 как любительского прототипа. Плюсы — работающий цикл, темы, бонусы, повторное использование рядов. Недостатки — монолитный класс, расширение Array.prototype, коллизии по целевой полосе вместо отображаемой позиции, ускорение на кадр вместо времени, таймеры с состоянием между забегами, отсутствие клавиатуры и обработки resize. Это оценка просмотренного кода и короткой игровой сессии, не полный аудит.
