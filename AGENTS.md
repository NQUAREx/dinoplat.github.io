# Dino Run development rules

## Context/tool economy and subagent orchestration

- Read instructions once per task; search with scoped rg and bounded output. Exclude dependencies, generated assets and historical logs unless relevant; batch independent reads and summarize large results.
- Keep one authoritative location per fact. Update current rules in place; avoid duplicate history and repeated validation narratives. Run relevant checks once per revision; repeat only for changes or unresolved failures.
- Delegate only independent, bounded work with explicit file ownership, constraints and expected evidence. Share minimal context; avoid duplicate investigation and overlapping edits. The main agent integrates results and owns final verification.
- Player-visible Russian/English names must use neutral physical, nature or technology terms; avoid magic, occult and mythical-character names. Preserve inventory IDs when renaming; ordinary mineral and astronomical terms are allowed. Technical tool names and attribution remain accurate.

## Scope, platform and licence

- Work only in NQUAREx/DinoPlat3d. Never modify/publish the separate live original NQUAREx/dinoplat.github.io.
- Static Three.js 0.186.1 + TypeScript + Vite application for GitHub Pages; no backend, CDN, physics/particle engine or new runtime dependency without need. npm run dev / build / preview must keep working.
- Owner approved GPL-3.0-only. Preserve LICENSE, public licence/source links and original imported VOX archives/attribution: hushenghao/dino3d commit cae7ed3da5646839e6aaa24f698b8c07cc3ffc85, ©2020 Abraham Tugalov. Never copy upstream gameplay code. Imported dinosaur/cactus VOX files are archival only, never runtime assets or model-builder inputs.
- Use local geometry/animation skills when applicable. I/O/model loading/authoring is async and parallel where useful. Fixed-step simulation, gesture state and RAF rendering remain synchronous: no promises/microtasks in hot loops.

## Terrain

- No floor atlas, floor textures or500m biome timer. LandscapeField defines desert-majority terrain with smaller lava fields and green lake oases, three vertex-colour covers each. Most ground stays within gentle low relief; sparse macro features create high mountains/deep basins and alternate-biome summit islands. Default height bounds -16.6..130m; pit depth14m/liquid bed4.8m. Archived art under art/ is not runtime. Never use path distance as terrain Z.
- Ground is224m/56² cells at4m, four persistent mesh banks: ground/bed/walls, water, lava, closed wooden bridge decks. Shared lattice vertices jitter radially <.85m; signed hazard/bridge masks clip each triangle into non-square polygons. CPU height/support must use those same warped triangles and interpolated masks. Bridge planks follow crossing direction, never hard-code worldZ. Avatar, collision, pickups, dust, shadow and camera use absolute ground elevation; jumps preserve absolute airborne momentum across slopes.
- Banks allocate10,762,752bytes of geometry buffers each on CPU/GPU plus157,536bytes CPU scratch. Four Lambert materials, no identity index buffers, rebuild allocation or growing cache; rebuild only when anchor/seed/revision/enabled changes. Bridge planks use a stable continuous coordinate and cheap colour bands, never extra support-triangle subdivisions or per-face tangents dotted with million-metre coordinates. Subtract an even integer before Float32 grain upload. One-query geometry cache avoids repeated triangle lookup; never cache unbounded history. Keep front-face winding/raycast/closure and pathological-mask regressions. Gray pit/ravine haze uses one normalized byte per vertex and Lambert shader depth mixing: no extra draw, texture, transparent stack or postprocessing.
- Rivers/ponds/lava/ravines/pits have visible beds/walls and are fatal when fallen into regardless of immunity. Bridges reserve traversable crossings, not invisible walkable water. Bird/tumbleweed numerical states and falling-obstacle pivots live in the fixed world pool, with reaction-time telegraph/cooldown. Dynamic colliders track poses; don't spawn render objects outside visibility. Scenery uses a bounded deterministic cache and instanced banks, no per-prop scene objects.

## Rendering, shadows and feedback

- Dinosaur body parts are surface-connected with blended skin weights. Fourteen bridges share seam positions/weights; every shared edge must have opposite winding, not just coincident vertices. Keep whole-surface manifold/winding/degeneracy and clip/crossfade tests and1182-triangle budget. Ordinary body material is opaque/front-sided; transparency only during requested immunity blink. Never hide mesh holes with DoubleSide. Rebuild skin thumbnails after geometry changes.
- Dust uses MeshLambertMaterial with scene day/night lighting, no emissive/unlit material and no casting/receiving shadow pass. Preserve one instanced bank/256 slots/eight triangles per puff.

- Collected items award immediately once;32 preallocated visual slots reuse three instanced meshes and one per-instance fade material. Lift1.2m/fade.45s, feedback-clock driven, origin-relative; no collidable remnant or runtime mesh creation. Clear on restart/dispose. - Shadow focus follows delayed camera direction without rotating celestial direction with the player. Map/casters refresh on reset/new chunks/manual light/context restore/large origin changes, not sun/moon label switches. Cacti cast; only ground receives, no unnecessary cactus-fragment lookups. - Dinosaur contact ellipse:16 triangles/one draw, black alpha, interpolated jump/yaw/duck/immunity/day/night, no second capture. - Floating feedback is twelve reusable 2D DOM labels above rendered dinosaur, not sprites/meshes. +1 coin/diamond/heart, -1 heart, MAX on full-health heart; .95s expiry, pool/restart cleanup and registerable future icons. Separate feedback clock runs through hit freeze, not manual pause.
