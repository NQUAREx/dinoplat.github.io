# DinoPlat3d: development rules

## Scope, licence and reference

- Change only `NQUAREx/DinoPlat3d`. Never publish changes to the separate live original `NQUAREx/dinoplat.github.io`.
- Static Three.js + TypeScript + Vite application for GitHub Pages. No backend, runtime Blender, external CDNs, physics engines or particle libraries.
- The owner approved GPLv3 for this project. Keep LICENSE, public GPL notice, original VOX sources and upstream attribution. Reference models: hushenghao/dino3d, commit cae7ed3da5646839e6aaa24f698b8c07cc3ffc85; original author Abraham Tugalov, 2020. Do not copy upstream gameplay code or add its old dependencies.
- Dinosaur reference: https://hushenghao.github.io/dino3d/ — eight run poses, jump pose and foot dust. Cacti are SEVEN original low-poly models, NOT voxel assets. Use broad bevels/faceted rounded stems, strong silhouettes and saturated cartoon greens/coral flowers, inspired by the general chunky Brawl Stars aesthetic without copying its assets. Keep pixel UI, voxel dinosaur/pickups and model-independent gameplay/colliders; do not silently migrate other assets. Keep our portrait rear camera/free movement, not upstream gameplay.
- New cactus art reference: owner's Brawl Stars environment screenshot (16 October): rounded toy-like bodies, soft baked vertex normals, restrained vertical green ribs, pale raised spots, short cream spines and coral/yellow flowers. Keep all details in one indexed vertex-colour mesh per variant; no decal layers, separate spine objects, outlines/postprocessing or material proliferation. Original models only; internet examples are visual reference, not imported assets. This does not authorize replacing the dinosaur, UI or authored biome atlas.

## Saturated child-friendly pixel design

- Canonical palette: sky **#73d8ff**, ink **#24374d**, lime buttons **#7be344**, button shadow **#43b52c**, warm cream **#fff2c3**, coral **#ff704c**, rich yellow/orange ground. Friendly, saturated cartoon colour, never washed-out mint/grey or realistic grit. Match 3D sky/fog (`Palette`) and CSS theme.
- Local Press Start 2P WOFF2 with Cyrillic; square stepped buttons, hard pixel borders, nearest-filtered pixel icons. No glass, rounded dashboard cards, gradients-as-decoration, bloom or postprocessing. The requested cactus ground silhouettes are the explicit lightweight shadow exception below.
- Menus centred. During RUNNING hide logo, slogans, help and decorative text entirely. Only the full-width top HUD (coin/diamond/lives/distance/record icons and values) and the **bottom-left** icon pause button remain. These are intentional exceptions to centred menus. Preserve safe-area spacing, >=48px pause hit target and short 320×568 viewport fit.
- HUD coin, diamond, heart, trophy and pause icons come from the original DinoPlat. Keep original files under art/hud-icons; publish only <=32px optimized versions. Sources/licences belong in ASSETS.md.
- Touch-only, portrait-only. Desktop gets a phone prompt without allocating a renderer or loading game models/terrain. Landscape pauses simulation and RAF; returning needs explicit resume. No keyboard/mouse game handlers or desktop layout.

## Mobile browser shell

- Support current iOS Safari/WebKit and Android Chromium browsers with WebGL 2 (target Safari/iOS 16+). Detect touch/any coarse pointer, including touch iPadOS reporting MacIntel; no UA-only gate. Do not claim support for old browsers without WebGL 2.
- Fullscreen API requires a trusted activation. Request it synchronously from Play/Resume or the pause-settings fullscreen button; feature-detect standard/WebKit API, catch denials and never prevent playing. No fullscreen requests on load, timers, synthetic activation or repeated prompts. Pause on leaving native fullscreen.
- iPhone Safari cannot be forced into fullscreen in an ordinary tab. Provide relative-path `manifest.webmanifest` (fullscreen/standalone fallback, portrait, start/scope ./), local 192/512 PNG icons and Apple 180 icon/meta. Explain Share → Add to Home Screen in pause settings/README. Do not promise automatic installation, offline play, hidden OS bars/gestures or successful orientation lock on every device. No service worker/stale asset cache added just for fullscreen.
- `MobileBrowser` owns viewport/fullscreen/long-press/lifecycle integration. Fixed document, no scroll/overscroll, user selection, callout, drag, tap flash or zoom. Capture contextmenu/selectstart/dragstart/WebKit gesture events. Cancel native touchstart/end and touch pointerdown defaults for game/buttons, not just canvas pointer events; clear selection ranges on selectionchange. CSS selection/callout suppression must cover pseudo-elements with !important; remove native button appearance. Preserve native range touch dragging and attribution-link navigation; these are explicit exemptions, not reasons to disable the guard globally.
- Use visualViewport dimensions (only at scale≈1), dvh/CSS fallback and safe-area envs. Coalesce browser chrome resize events in one RAF; do not resize the WebGL buffer if CSS dimensions and DPR are unchanged. Change dimensions + DPR once via setDrawingBufferSize. Cache touch midpoint on resize instead of querying layout in pointermove.
- Pagehide/freeze/background/fullscreen exit clear pointer capture, pause physics, stop RAF/vibration and suspend Web Audio. BFCache pageshow redraws but must not auto-resume the run or held input. Resume audio/fullscreen only on user activation; dispose all shell listeners/RAF on teardown.
- Run `npm run test:mobile` after building, with Playwright Chromium/WebKit installed. Engine/device emulation is not testing physical iOS/Android hardware; report that limitation. Home-screen modes and missing/denied fullscreen need separate tests.

## World and collision rules

- **No road boundaries and no fixed lane count.** X is continuous and unbounded in both directions. Forward is logical world Z; Y is jump height. Never restore X clamping, white lines, edge rails or a road-shaped ground mesh.
- `Simulation` is DOM/Three-independent. World/physics numbers are Float64; subtract player world position before sending any Float32 positions to GPU. Camera, avatar and ground stay near local origin even after millions of metres. Bounded tile UV offsets preserve pixel precision.
- Use ONE `RenderPose` interpolated origin for ground, cacti, dust and camera. Avatar stays at local X/Z zero. `TerrainSurface` anchors mesh/UVs to fixed 8m world cells, moving its transform continuously relative to RenderPose. Texture uniforms change on anchor/biome changes, not to scroll a stationary camera-local plane. Hash the FULL local+anchor tile ID modulo 65536 inside GLSL as well as on CPU; otherwise negative/wrapped origins reshuffle variants. Biome phase uses mesh anchor minus simulation segment and local vertex Z, preserving signed interpolation just before 500m.
- `WorldSpawner` uses a fixed 2D numeric chunk ring: at most `Rules.poolSize = 1170` slots (13×9 chunks, six obstacle + four pickup candidates each), no growing maps/history/scene objects. Chunks are storage keys only: X/Z are independent continuous random coordinates, never aligned rows or jittered lanes. Refill only on chunk/window changes; numeric guard slots prepare incoming objects. Density is deterministic by natural distance-based speed; hard-core thinning prevents interpenetrating cactus clusters. Pickup candidates use a separate weighted group and never alter the original six cactus candidates/RNG. Reject pickups near all potential cactus positions deterministically, independent of window order.
- Keep continuous safe routes spaced 32m apart with derivative <=.081. Reserve actual rotated cactus extents plus avatar radius, reaction margin and route slope over the full Z extent. Route starts at X=0; no route lines or avatar lanes. Verify max-speed reachability with 300ms reaction and all lives, not survival masked by immunity.
- Swept X/Z collision uses actual old/new player positions and jump height. Cactus collider extents come from normalized model bounds rotated by the instance yaw. Decorative dinosaur head/tail do not enlarge the stable body collider. Grounded jump only; damage immunity prevents repeated hits on the same cactus, three lives, restart resets run state without reallocating pools.
- Cull **full** object AABBs with the actual camera frustum; retain partially visible trailing cacti. Ring retirement must remain outside every supported frustum. No fixed -4m visual cutoff.
- GPU correctness is separate from CPU correctness. Three r186 traverses visible objects BEFORE increasing its frame counter, but updates shadow casters AFTER. Cached shadow frames can therefore leave an upload stamp that skips the next visibility-pass upload. `View.draw` starts a fresh `renderer.info.render.frame` upload epoch before render; do not remove this without passing actual GPU readback tests. Do not change simulation time, shadow cadence or create buffers/meshes to work around it. `tests/instance-motion-browser.mjs` checks GPU positions/yaw/ground bases immediately before draws, through capture/noncapture frames and chunk boundaries. Readback is TEST-ONLY; never put synchronous GL inspection in RAF.

## Components and extensions

- Small OOP components with explicit ownership: GameApplication/GameUI, Simulation, WorldSpawner/ObjectRegistry, ObjectRendererRegistry/InstancedObjectType, ModelLibrary, AnimatedDinosaur, FootDust, Ground, CameraRig, Haptics, Wallet, Health, BonusSystem, GameEvents, Input/GestureRecognizer.
- `ObjectDefinition` describes kind, spawn group/weight, colliders, reward/bonus/healing, animation and optional destruction metadata. Active types: cacti, coins, diamonds and hearts. Pickup group weights **250:10:1**; do not mix their weights into cactus selection/density. Bonus/enemy drops, destruction and debris remain disabled. `DestructionDefinition` is a reserved contract, not an implemented break mechanic.
- Pickups are genuinely solid voxel volumes matching the original HUD silhouettes/palettes, never sprites, textured planes, smooth spheres or gems. Editable generated VOX sources live in `art/collectibles/`; `npm run collectibles:build` authors them from HUD icons with offline ImageMagick and rebuilds the single cached GLB. Three shared indexed geometries, one opaque vertex-colour material, three instanced banks. `PickupMotion` samples ONE shared 2.4s phase (Y-axis rotation + ±0.1m bob); all pickups stay in phase. Simulation and interpolation use the same game clock, frozen on pause/reset. Use conservative yaw-invariant pickup bounds and bob-aware swept vertical overlap/culling; never advance separate per-object animation timers.
- A collected item is consumed once while its chunk is retained. Wallet balances are cumulative: Simulation.reset must NOT reset them. `CurrencyCookies` restores/saves `dinoplat3d-wallet-v1=1.coins.diamonds`, scoped to the Vite BASE_URL path, Max-Age one year, SameSite=Lax, Secure on HTTPS. Coalesce pickup writes in one microtask; flush on pause/disposal/navigation. Never read/write cookies in RAF. Validate nonnegative safe integers; corrupt/blocked cookies must not break gameplay. Browser deletion/privacy limits can remove persisted balances; this is client-side prototype storage, not a secure server economy. Hearts restore one up to three, never revive/clear immunity and are consumed at full health; emit Heal only on actual healing.
- Collider baseY supports floating items/flying enemies; use it consistently in numerical spawn, vertical body overlap, frustum bounds and instance transforms. Speed modifiers must still obey the max-speed timing budget of the proven route; expanding that budget also requires changing generation/proof tests.
- Register a new object definition and renderer rather than hard-coding it into Simulation. Model geometries/materials belong to asset/view owners; instance banks own only instance buffers. Bonuses use a fixed active-slot pool and definition registry; defaults contain no active bonuses.
- Event bus sends small numeric payloads. Haptics and camera effects subscribe once and unsubscribe on disposal. Vibration is optional, switchable, throttled and feature-detected (iOS may not support it). Never promise haptics work on every phone.
- CameraRig supports event-driven `setPose` and `impulse`, distance-synchronised step bob and reduced-motion support. Baseline Y=8.5/Z=12 (lowered from 10), look Y=1/Z=-5, FOV 50°; far 96m and fog 36–84m. Pause settings persist vibration, sound and shake multiplier 0–3 (default 1). Reduced motion overrides shake. One reusable Web Audio voice unlocks only on user activation; pause/mute/dispose stop sound.
- Cacti geometry and model-derived colliders are both scaled exactly 2× at load/registry creation, never every frame. Jump velocity 13.3 preserves useful clearance. On damage: two seconds of immunity, alternating 50%/100% dinosaur opacity, start speed 12m/s; expiry restores distance-based speed. HUD lives are three filled/empty hearts, never a numeric counter.
- Swipe DOWN in air sets continuous fast descent (22m/s minimum), never teleports through objects; landing emits once. On ground, duck for .85s with .083s blending, body height 1.3→.65m and matching visual compression. Swept collisions interpolate both feet and body top; future overhead obstacles use existing baseY. Jump cancels duck; pause freezes timers; restart clears duck/dive. Do not add active overhead obstacles until asked.

## Sun/moon, lit terrain and cached shadows

- `DayCycle` uses simulation time: starts at 9:00, **360s per day**, freezes in pause. `LightingRig.setTimeOfDay(hours, automatic=false)`, `setSunPosition(x,y,z)`, `?time=18` remain extension/debug controls.
- One actual DirectionalLight `key` smoothly changes sun/moon colour/intensity along a continuous artistic orbit; the sun/moon label must NEVER switch direction or ambient settings. No second hidden sun/shadow pass and NO visible moon mesh. Blend ambient, ground tint, fog and shadow strength continuously across dawn/dusk/midnight; use interpolated simulation time and smooth sky stops. Keep the orbit above grazing angles to bound shadows. One HemisphereLight gives ambient. Ground uses standard MeshLambertMaterial with normals and receiveShadow.
- `CachedShadows` owns no per-cactus mesh: reuse original instanced cactus banks as casters; only terrain receives shadows today to avoid unnecessary cactus-fragment depth lookups. Future props can opt into reception/self-shadowing. Include offscreen cacti only when their projected bounds can enter the view. One **256² BasicShadowMap** without filtering/postprocessing; one target with native depth texture. Dark directional shadows work day AND night, including minimum quality. Do NOT restore quality-based shadow disabling (the previous ~170m disappearance).
- Disable renderer/light shadow autoUpdate. Capture at 8Hz, 4Hz at quality<=.55; force refresh on new world chunks/reset/manual-light changes, large origin jumps and context restore, NOT a sun/moon label change. Between captures, rebase the cached shadow matrix by the player-origin delta. Snap map texels in the actual shadow-camera basis. Dispose each target once on teardown/context recovery; Three's target-disposal handler releases its native depth attachment. Do not dispose that texture a second time.
- Retain an 8m guard around projected caster bounds: a cached map can live .25s while the player advances 6m. Tight per-frame caster culling causes edge popping. Do not submit the whole surrounding disk. Original cactus transforms/ground-zero feet remain fixed across ring updates; full model-derived yaw bounds drive colour culling.
- `DinosaurShadow` is a separate 16-triangle black contact ellipse, one draw/no texture. Update position, heading, footprint and opacity from the interpolated avatar every frame, accounting for jump height/duck/immunity/day-night; never bake the moving avatar into the throttled static-cactus map. This is an approximation, not a silhouette or uneven-ground projection. Black alpha only darkens even at night. Walking bob fades in/out on jump/land/pause, never instantly resets its amplitude.
- Budget: <=21 draws on a capture frame / <=14 otherwise; <=22 warmed geometries and **3 GPU textures** (terrain array + shadow target colour/depth). Hardware/driver memory varies. Reuse cached matrix update ranges and upload only live prefixes; no addUpdateRange allocations in frame loops.
- The owner explicitly requested keeping the existing shadows unchanged during the cactus-detail/jitter update. Preserve map size/type, capture cadence, intensity, light motion, receiver settings and dinosaur contact shadow; model silhouettes naturally follow the new geometry.

## Touch classification

- A new touch is PENDING: **do not steer on pointerdown**. Upward motion resolves to JUMP, downward to DIVE/DUCK; neither may move X, even briefly. Vertical classification is exclusive and fires once. A stationary hold resolves after 40ms (formerly 140ms); horizontal intent commits at >3px immediately. A moving pending finger must not time out while preparing a slow swipe. Zero-delay stationary steering and guaranteed zero drift on a later vertical swipe are incompatible; do not hide this tradeoff or roll back physics.
- Classification is exclusive: a committed hold cannot turn into a jump later. Release it and start a separate upward swipe. During a hold, crossing the screen midpoint reverses X. Release/cancel/lost capture/pause/rotation/visibility loss/reset clear input. No rollback of already simulated movement or collisions.
- Keep recognition independently unit-tested, plus real touch-event browser tests for unchanged X throughout a jump gesture.

## Ground assets and performance

- 16 terrain types change every 500m with equal configurable weights, no immediate repeat; terrain RNG must not affect world spawning.
- Tiles cover **2.5×2.5m**, half the previous 5m size. Four non-mirrored seeded variants per material with prepared collars. `TerrainSurface` is one indexed 192m mesh, 24×24 cells / **1152 triangles**, normals and heightAt/setHeightProvider hooks for future relief/decor anchors. It remains flat for current flat-world physics; do not claim uneven-ground locomotion is implemented. Recycle the same geometry; no mesh/tile creation each frame.
- Prepare periodic patterns/variant seams with offline minimum-error hard cuts (`tools/pixel-quilter.mjs`), never blur/average opposite edges into straight grid bands. Shader texture gradients must be calculated before region branches and passed explicitly to textureGrad; connector UV resets must not select an averaged last mip and produce a thin straight stripe.
- One local DataArrayTexture, 97 independent 128² layers: 64 base variants + stone + 16 entries + 16 exits. Albedo is injected into standard Lambert via onBeforeCompile, preserving its normal/light/fog/shadow pipeline. Nearest magnification, LINEAR_MIPMAP_LINEAR minification to reduce subpixel shimmer at the smaller scale. No biome overlays; GPU RGBA incl. mipmaps ~8.1MiB; upload once. Shadow lookup is a separate low-resolution depth sample, not a second terrain overlay.
- Use EXACT authored transitions from `art/terrain-transitions-attached.jpg` (user attachment): crop 4×4 rectangular tiles, retain full drawn border and rocks, rotate exits by 180° offline. Do not replace interiors with base/stone masks again. Only narrow endpoint collars get hard-cut seam preparation; browser test compares preserved interiors with the attachment.
- Every boundary: **1.25m painted A→stone, 2.5m stone, 1.25m rotated stone→B**. Preserve authored artwork, shared stone and endpoint phases, no N² assets. Original images stay in art/, never dist/.
- `tools/low-poly-cacti.mjs` is the editable original source for seven cacti (316–668 triangles each, cap700), built offline into the shared GLB with model-derived bounds. Remove pole degenerates; retain authored smooth body/bevel normals and sharp spine/cap normals. Never use fragment-derivative flatShading for cacti. Ribs use baked vertex colours; raised five-sided areoles and triangular solid spines share the same indexed mesh/material. Pack linear colours as normalized Uint8. Preserve all seven size envelopes. No runtime VOX cactus loader/generator; imported cactus VOX files remain archival GPL source only.
- Preprocess dinosaur/pickup VOX with colour-aware greedy meshing/indexed vertices; retain their palettes/animation. One cached mixed-model GLB, no textures/rig/decoder. Run poses swap preloaded geometry; never create/dispose meshes per frame. Foot dust is a fixed 32-particle opaque instanced pool, no shadows or external engine.
- I/O and preparation are async (parallel loading, shader preparation, authoring scripts). **Fixed-step simulation, input state and RAF rendering must stay synchronous**: do not wrap frame work in promises, async tasks or microtasks. This is a performance requirement, not missing asynchrony.
- No allocations in hot loops, no per-obstacle meshes, no unbounded caches, minimal dependencies. Reuse matrices/frusta/bounds/materials. Cap DPR and physical buffer at 900k pixels; retain adaptive resolution and lifecycle cleanup. Dispose textures/geometries/instance buffers/listeners exactly once, including HMR and asset failure paths.

## Verification

- Run npm test, npm run build and npm run test:browser. Verify infinite X both ways, bounded/repeatable 2D windows, safe max-speed route, yaw-aware swept collision/jump/lives, separate gestures, all animation/cactus variants, dust, painted connectors, viewport/pose changes, HUD, pause, optional storage/vibration, WebGL recovery and asset errors.
- Test huge world coordinates with bounded GPU positions; visually inspect running/paused/short portrait and terrain border screenshots. Warm all poses/variants before comparing resource counts across 100 restarts. Do not compare cold geometry counts with warmed counts.
- Record measured draw calls/resources and honest platform limits in VERIFICATION. Cloud Chromium/SwiftShader is not a physical weak phone; never promise a device FPS without measuring it.
- Remove superseded unused runtime assets/tools; preserve original imported model art and licences. Keep source readable and formatted. No compatibility aliases for removed lane APIs just to keep obsolete tests passing; replace tests with the new mechanics.
